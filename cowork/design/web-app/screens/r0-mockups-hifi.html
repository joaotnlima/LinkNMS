Build notes — what changed from LINA-20 wireframes

  • Surface 1 is now the four-pillar status panel (Scope · Time · Cost · Quality), per PM spec — replacing the single-budget dashboard. Each pillar is a RAG state carried by colour + label + icon. Time reads “changes added N days” and is green at zero; it never claims on-track-vs-baseline. Cost = current vs baseline. Scope/Quality are qualitative.
  • Change-order form captures cost impact, a scope-impact note, schedule impact (days + note), and a quality flag + note — all surfaced again in the CO detail.
  • Proposer-vs-approver is explicit: the approver sees Approve/Reject; the proposer sees the same record with a locked “can’t approve your own change” state (see Mobile · Dark, Surface 3 pair).

Tokens & theming

  • Light tokens mirror design-system/tokens.json. Dark is a derived theme: brand Owner Blue / Builder Orange preserved (brightened for contrast), semantic RAG re-tuned, Paper→ warm-dark surfaces. Switch via [data-theme="dark"] on the app root; every component reads CSS custom properties only.
  • Type scale, spacing (4px base), radii (6px control / 10px overlay), and the single elevation token follow cowork/design/web-app/DESIGN.md. Monetary/quantitative values use tabular figures.

Responsive contract

  • Mobile-first (base < 640px): single column, bottom tab nav (Home / Decisions / Budget), bottom-anchored primary action ≥ 52px, all targets ≥ 44px. This is the on-site primary target.
  • Desktop (lg ≥ 1024px): the four surfaces become a persistent left rail + main pane + right detail drawer — the CO opens in-place beside the record instead of full-screen. Reading pane caps ~1200px.

Accessibility & voice (mandatory)

  • Colour is never the sole signal — party by label + position, status by label + icon. RAG chips pair hue with text + glyph. Contrast holds in both themes.
  • Copy uses tamper-evident (never “tamper-proof”); no unbuilt capability in the present tense.
  • Neutral referee: no owner-first or builder-first weighting; planned/actual and owner/builder stay on the blue/orange axis, health stays on green/amber/red — the two never collide.
