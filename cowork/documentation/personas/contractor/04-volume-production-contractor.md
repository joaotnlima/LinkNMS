# The volume / production contractor

## Who they are

Builds several similar homes (housing developments, serial construction),
standardized processes, a relationship with each client that's more
transactional than close. Probably the variant least aligned with
LinkNMS's original purpose ("turnkey" build for an individual, anxious
owner) — worth having written down precisely so it isn't confused with
the [growing contractor](./02-growing-contractor.md), which looks similar
but isn't.

## Motivations

Repeatability and speed. Each house is a production unit, not a unique
project — the value is in doing the same thing well and fast many times
over, not in customizing.

## Pain points

- Manually re-entering the same task and budget structure for each new
  house is pure waste of time.
- Individual clients are less hands-on than in the classic turnkey build
  — a rich client portal is over-investment for this case.

## Behaviors

- Fast, repetitive data entry; any friction multiplies by the number of
  units.
- Probably already uses (or would like to use) some broader form of
  management system (ERP, public works tools) — this tool would have to
  coexist with that, not replace it.

## Where this differs from other variants of the same role

It's the opposite of the
[premium contractor](./03-premium-contractor.md) on the
"standardization vs. customization" axis, and it differs from the
[growing contractor](./02-growing-contractor.md) because their builds are
interchangeable with each other — the value of "seeing everything
aggregated" is lower when the projects are copies of one another, and the
value of "reusable templates" is much higher.

## Implications for features

- **In favor of**: reusable task/budget templates across projects — not
  identified in any tier of the current roadmap because it assumes
  multi-project, which doesn't exist yet.
- **Against**: a rich client portal with detailed approvals — for this
  variant, it's disproportionate effort relative to value.
- **Priority note**: this variant only becomes relevant if LinkNMS
  decides to target volume construction companies as a segment — it's
  not the implicit target market in the rest of the documentation (owner
  - contractor, one project). It's worth more as "we know it exists and
    is different" than as a near-term design target.
